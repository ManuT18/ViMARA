## 2. Logic Chain
1. **Context & Problem Alignment**: WebAR running in mobile browsers (Android Chrome, iOS Safari) faces tight memory caps, lack of dedicated VRAM, and main thread execution constraints.
2. **Software Export Reality (R1 Integration)**: Architecture students use diverse CAD tools. While Blender and Rhino 8 export `.glb` natively, SketchUp Free Web only exports STL (plugins locked), AutoCAD 2023+ and Revit 2023+ export OBJ natively, and SketchUp Pro/Rhino 7 support plugins or fallback exports.
3. **Format Technical Benchmarking (R2 Integration)**: `.glb` is the optimal web transmission format due to zero-copy ArrayBuffer loading, PBR material consistency, and support for Draco geometry compression and KTX2 texture supercompression. ASCII formats (OBJ, DAE) incur heavy text regex parsing overhead and GC pauses. Non-indexed formats (STL) waste VRAM by duplicating vertices ($6V$).
4. **Architecture & Pipeline Design (R3 Integration)**: Adopted a 3-tier model: Tier 1 (`.glb`/`.gltf` WebAR core), Tier 2 (`.obj`+`.mtl` & `.stl` universal user import), Tier 3 (`.usdz` iOS AR Quick Look dynamic fallback). Designed a $0-cost in-browser WebAssembly pipeline (`ModelPipeline`) that converts Tier 2 uploads to Draco-compressed `.glb` Blobs in client RAM, with pivot normalization and scale detection.
5. **Synthesis**: Consolidated all technical benchmarks, equations, flowcharts, code implementations, and step-by-step CAD export guides into `3D_File_Format_Standards_ViMARA.md`.

## 3. Caveats
- iOS Safari requires USDZ for native AR Quick Look; the client-side pipeline uses Three.js `USDZExporter` on-the-fly when iOS devices are detected.
- Extremely large architectural CAD files (>50 MB or >1.5M polygons) may exceed mobile browser heap memory; an optional serverless microservice architecture (`gltf-pipeline` / `assimp`) is specified as a fallback for high-complexity models.
